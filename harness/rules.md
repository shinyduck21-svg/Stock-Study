# Stock-Study 하네스 규칙

이 문서는 이 저장소에서 AI 에이전트가 작업할 때 따르는 프로젝트 로컬 운영 규칙이다.

## 기본 작업 흐름

1. 편집 전에 먼저 확인한다.
2. 수정 범위를 좁게 유지한다.
3. 사용자 데이터와 관련 없는 로컬 변경사항을 보존한다.
4. `npm.cmd run build`로 검증한다.
5. 완료하지 못한 검증이 있으면 명확히 밝힌다.

## 콘텐츠와 미디어

- `public/data/posts.json`은 운영 콘텐츠로 취급한다.
- 게시글 하나를 고치기 위해 `posts.json` 전체를 대량 재포맷하지 않는다.
- Drive 미디어는 직접 다운로드 경로와 preview fallback 경로를 모두 지원한다.
- 재생 버튼은 조용히 실패해서는 안 된다. fallback 또는 명확한 오류 상태를 보여준다.

## 프론트엔드

- 모바일과 데스크톱에서 UI 컨트롤 크기와 위치가 안정적으로 유지되게 한다.
- 버그 수정 중에는 넓은 범위의 시각적 재설계를 피한다.
- `src/App.jsx`의 기존 컴포넌트 패턴과 `src/App.css`의 기존 스타일을 우선한다.

## 검증

- 코드 변경 시 필수: `npm.cmd run build`.
- 관련 있을 때 선택: 로컬 Vite 서버 `http://127.0.0.1:5173/Stock-Study/`.
- 알려진 주의사항: `npm.cmd run lint`는 현재 기존 실패를 포함하므로, 관련 없는 좁은 수정의 차단 조건으로 보지 말고 참고 신호로 사용한다.
